PIXELCLASH

A LAN auto-battler where players prompt an AI helper to write their units in JavaScript, then watch them fight on the big screen.

For 2-8 players, built for a Kids Coding Day. Players only describe what they want; the AI helper writes the code, the game server checks it, prices it and runs it in a sandbox.

How a round works

A match is several rounds, free-for-all or in teams, on a map that fits the player count. A facilitator runs each round from /admin through four phases.

  1. 1

    Plan

    Players talk to their AI helper to design new units or improve old ones, then pick which unit and building types to field and press "I'm ready!". The projector shows the timer and the join QR.

  2. 2

    Placement

    Each player places copies of their picks in their zone of the arena, within a budget. Armies stay secret until the facilitator presses START.

  3. 3

    Battle

    The units fight on their own, running the code the AI helper wrote. The battle plays live on the projector and on every player's /play.

  4. 4

    Results

    Ranking, points and badges on the projector, and a per-unit report for each player, including any errors to hand back to the AI helper. Then the next Plan starts.

After the last round comes an awards ceremony on the projector.

What players do

Player laptops need only a browser. Everything happens in /play: the AI helper's terminal sits side by side with the game.

Prompt the AI helper

Each player gets their own AI helper (Claude Code or the OpenAI Codex CLI) in the browser, already logged in. They describe the unit they want; the helper writes the JavaScript, validates it and submits it to the game.

Edit the code

Any unit can be opened in the built-in code editor from My Units, with live checks and a price breakdown before saving a new version.

Read the unit guide

/guide explains everything a unit can do, with the numbers from this game, built from the live config.

Replay past battles

Earlier rounds keep their results and a replay, with pause, 1x/2x and a scrubber.

Features

What's in the box.

Elements and combos

Fire burns, ice slows and lightning can zap a neighbour. Elements combine into synergies such as shatter, kindle and brittle.

Support units

Units can heal allies or give off haste, might and shield auras.

Walls and towers

Walls are solid blocks that stop everyone; towers stay put and shoot. The host can switch walls off for a match.

Factories and minions

Factories build grunts, archers, runners, brutes or medics, give them squad orders, and can steer each one with an optional updateMinion().

Teams

Free-for-all or 2-4 teams, auto-balanced or arranged by the host. Unequal teams are allowed, with a budget per team.

Projector screen

/screen shows the arena, timers, join QR, ready ticks, live battles, the scoreboard and an awards ceremony after the last round.

Facilitator /admin

A setup wizard for the AI seats, match setup with map preview, phase and timer controls, player and seat management, and a live config editor.

Sandboxed, deterministic sim

Player code runs in isolated-vm with tick deadlines. The battle runs at 60 ticks per second with a seeded random number generator: same inputs, same battle.

How it runs

Three kinds of machine on a local network. For a try-out, everything can run on one.

2-8

Player laptops

  • A browser, nothing else
  • /play: the game plus the AI helper pane
  • Projector: /screen; facilitator: /admin
HTTP + WebSocket over the LAN
Node

Game server

  • Web pages, REST, MCP and WebSocket
  • Validator, isolated-vm sandbox, battle sim
  • Terminal proxy to the AI seats
  • Needs no internet
Terminal traffic out, MCP tool calls back
Docker

AI session host

  • One container per seat, 1-8
  • Claude Code or Codex in each seat's kit folder
  • The only machine that needs the internet

↓ Anthropic / OpenAI API

  • The AI helper's terminal is shown inside /play through the game server's proxy, so players never see a seat password.
  • The helper submits units with MCP tools such as validate_unit and submit_unit.
  • Full details: docs/architecture.md.

Get started

Game server: Node 24 LTS (22.13+ also works) and make. AI session host: Docker with Compose v2, about 1 core and 2 GB RAM per seat, internet access and a Claude account (and/or an OpenAI login for Codex seats).

Try it on one machine

game server
$ git clone \
    https://github.com/redging-very-well/ai-coding-arena.git
$ cd ai-coding-arena
$ make install    # npm ci
$ make build
$ make start      # LAN URLs, a /play QR, the admin password
$ make bots PLAYERS=3   # optional: bot players

Open http://localhost:8080/admin, /screen in another window and /play in a third. Without AI seats, /play still works with the starter units and the built-in code editor.

Add the AI seats

AI session host
# copy this from /admin -> AI seats -> AI session host setup
$ make seats \
    PIXEL_CLASH_URL=http://<server-LAN-IP>:8080 \
    SEAT_SECRET=<from /admin>
$ make seats-ps                # all "running (healthy)"
$ make seat-check SEAT=1

The /admin setup wizard walks through it. Then enter the AI session host's address in /admin → AI seats; every running seat turns green. Players open /play, join with a name and a 4-digit PIN, and get a free AI seat.

Event-day setup, firewall rules and troubleshooting are in the README and sessions/README.md.
